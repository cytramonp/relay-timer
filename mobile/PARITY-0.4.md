# Mobile 0.4 parity and release boundary

Native baseline: the verified 0.3 Meeting/dial/feedback implementation, merged with the published web timer library at `5554382`. Access rules and billing-worker baseline were read from the owner's parallel web working copy on 2026-10-30; that working copy was not reset, edited or deployed by this task.

Implemented: nine primary timers; all 27 current specialty profiles with matched web defaults and exact board engine; independent starts/pause, stages/turns/laps, manual tea handoffs, elapsed-time restoration, clock/stage editing, add/remove/reorder stages, custom routine, local setup save/load and JSON import/export, CSV including lap splits and scores, sports score controls, favorites and chosen start timer. Themed kitchen examples/serving planner, editable and saved speech signal thresholds, smooth UI-thread breathing visualization, brushing zones, meditation digit hiding, bundled sound and guide art are included. Native boards currently require the screen open for cues and scheduled dish starts; they do not schedule OS background alarms.

Access: same 10-day **and** 10-start trial, two starts per UTC day afterward, server-side idempotent reservation, customization gates and preserved local setups. Pause/resume/rounds/speaker handoff retain an existing session. Running primary timers continue without new access checks. The default anonymous identity is separate from the website's signed-in Google identity. An optional Credential Manager/Firebase Google login adapter is prepared: it links a new Google identity to the anonymous UID or signs in to an existing website identity, then refreshes account access. It needs a configured OAuth client and registered Play signing certificate and has not been exercised with an actual account. Google Play purchases are disabled pending the owner's store setup and real tests.

Prepared store integration: native Billing Client 9.1.0 localized annual product query, Play payment sheet, purchase updates, pending/cancel feedback, restore on foreground, server verification and acknowledgement against Google, annual base-plan and account binding, receipt lifecycle checks and single current restore ownership. These paths are unit/compile candidates until real Play license tests pass. No Stripe web checkout is opened by the native paywall.

Differences still requiring later work or owner configuration: website private Google library synchronization; account sign-in activation/deletion verification; website-only browser interactions such as browser fullscreen/Picture-in-Picture; specialty background notifications; payment-enabled release after Play configuration. GPS, synchronized remote clocks and safety-critical instrumentation are not implemented. Store production readiness is recorded independently in `store/GOOGLE-PLAY.md`.
